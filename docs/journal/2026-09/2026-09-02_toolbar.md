# Declarative formatting toolbar

## Context

The three editing surfaces (`source`, `in-place`, and the source pane of `split`) were complete, but there was no chrome — no buttons, no formatting shortcuts. ADR-002 §2/§4/§5 committed a declarative toolbar, an inline-SVG icon set with a `icons` override, and a small keyboard-shortcut set to the first release. This entry lands all three, at the "default set, hide and reorder" configurability tier (see the ADR-002 amendment below).

## What was built

**Command registry** (`src/toolbar/commands.ts`). A flat list of `ToolbarCommand` records — `{ id, title, run(view), isActive(state), keys }` — built from small pure edit primitives. The primitives are split across three files to stay under the 200-LOC ceiling:

- `src/toolbar/inline.ts` — `toggleWrap` (bold `**`, italic `*`, strike `~~`, inline code `` ` ``, inline math `$`; wraps an empty caret with the caret parked between the marks, unwraps when the selection is inside or around an existing pair), plus `toggleLink` — wraps the selection as `[text](url)` with the `url` placeholder selected, or, when the caret is already inside a `[label](url)`, **unlinks** it (the label text stays, the `](url)` wrapper goes).
- `src/toolbar/block.ts` — `toggleHeading` (sets, swaps, or clears an ATX prefix), `toggleLinePrefix` (blockquote, bulleted list, numbered list, task list — adds the prefix to the lines that lack it, strips it when every non-blank line already carries it; the `insert` may be a function of the 0-based position so the numbered list counts `1.` `2.` `3.` rather than stamping `1.` on every line; a `siblings` regex makes the three list markers mutually exclusive, so pressing one on a line that already carries another swaps the marker in place instead of stacking `- 1. - …`), `toggleHorizontalRule` (inserts `---` on its own line — a blank line first when the current line has text, so CommonMark reads a thematic break and not a setext H2 — or removes the rule the caret is on), and `toggleFrontmatter` (a plain toggle: with no `---` block it wraps the top of the document — line 1 through the last selected line — in fences so a typed-then-selected key list converts in one click; with a block present it removes only the two fence lines and leaves the YAML text in place). `frontmatterRange` was lifted from `src/inplace/frontmatter.ts` to a shared leaf `src/frontmatter.ts` (the same pattern as `src/wikilink.ts`), so the toolbar reuses it without pulling the lazy in-place chunk into core.
- `src/toolbar/fence.ts` — `toggleFencedCode` (wraps the selected lines in a ` ``` ` fence, or unwraps the block the caret sits in, found via the syntax tree) and `toggleMathBlock` (the same for a `$$` … `$$` block — the Markdown grammar has no math node, so the fence pair is found by pairing `$$`-only lines across the document).

`isActive` is a best-effort read of the doc around the selection — a line-local regex scan for the inline marks and link spans, a prefix test for the line commands, a `FencedCode` syntax-node lookup for the code block, and a `$$`-line pairing scan for the math block. It drives the button's pressed state only; it is not correctness-critical. Two disambiguations are deliberate: the inline `$…$` scan skips an empty `$$` pair and any `$` flanked by another `$`, so a caret on a `$$` fence lights `mathBlock`, not `math`; and the `$$` pairing scan counts a caret sitting _on_ an opening `$$` as inside that block.

**Built-in ids.** `undo`, `redo`, `h1`, `h2`, `h3`, `bold`, `italic`, `strike`, `link`, `bulletList`, `orderedList`, `task`, `quote`, `hr`, `frontmatter`, `table`, `code`, `codeBlock`, `math`, `mathBlock`. The default bar shows all of them, `"|"`-separated and grouped by kind: history · headings · inline text (with `link`) · the three list markers · block structure · code and math. (`table` grew a cell-navigation keymap and live pipe alignment after the milestone — its own [note](./2026-09-02_table-editing.md).)

**Keyboard shortcuts** (`src/toolbar/keymap.ts`). A `Prec.high` keymap built from the commands that declare `keys`: `Mod-b` / `Mod-i` / `Mod-k` and `Mod-Alt-1..3`. It is folded into `baseExtensions`, so the shortcuts work on every CodeMirror surface whether or not the visible bar is mounted. Undo/redo keep their `historyKeymap` bindings and declare none here.

**Icons** (`src/toolbar/icons.tsx`). One glyph per command id — inline-SVG strokes, with `H1`/`H2`/`H3` as text, `fm` in monospace, and `hr` as three dashes. No icon package enters the dependency tree. `DEFAULT_ICONS` is the fallback; a consumer passes `icons={{ bold: <MyIcon/> }}` and only the ids they name are replaced — the render is `icons?.[id] ?? DEFAULT_ICONS[id]`.

**Wiring.** `SourceView` already reported its `EditorView` up through `onViewChange` (that is how `split` does scroll-sync); `InPlaceView` and `SplitView` gained the same passthrough. `Stylo` lifts one `view` state, hands `onViewChange` to whichever editing surface is active, and renders `<Toolbar>` above it for every mode but `preview`. `toolbar={false}` drops the bar; `toolbar={{ items: [...] }}` picks and orders the buttons. `readOnly` renders every button disabled. The bar re-reads `isActive` on `keyup` / `mouseup` / `input` / `focus` / `blur` from the view's content DOM.

**Styling.** `.toolbar` / `.toolbarButton` / `.toolbarSep` added to `stylo.module.css`, all `--stylo-*`-token driven, with a hairline bottom border. `.source` and `.inplace` gained `flex: 1 1 auto; min-height: 0` so the surface fills the space under the bar when the host bounds the height.

## Verification

`typecheck`, 76 Vitest tests (24 new in `test/toolbar.test.tsx`), `build`, and `format:check` all pass. The build emits no new chunks — the toolbar lands in the core entry (`stylo.js`, ~2.4 kB gzip) and the keymap in the shared `useCodeMirror` chunk; both pull only `@codemirror/*` packages already present.

`test/setup.ts` gained a jsdom stub for `Range.getClientRects` / `getBoundingClientRect`, which CodeMirror calls on any `scrollIntoView: true` transaction and jsdom does not implement.
